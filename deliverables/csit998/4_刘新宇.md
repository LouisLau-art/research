## Summary for the integrated proposal

Module 4 supplies the relationship-recommendation capability of the platform. Given an undirected
social graph, it scores every non-edge and returns, for each queried node, a ranked list of candidate
connections with a calibrated probability and a human-readable justification. The method modifies
the random walk that DeepWalk and node2vec use to generate training sequences, biasing each hop
towards structurally similar neighbours so that the learned embeddings carry local structural
information rather than having it added after the fact. The approach is evaluated against three
heuristics and three representation-learning baselines on three public graphs, over ten independent
edge splits with paired significance testing.

Two results are reported honestly. First, the structural weighting itself produces no practically
meaningful gain: on Cora and Citeseer it is statistically indistinguishable from DeepWalk, and on
Facebook it is detectable but negligible (ΔAUC = +0.0016). Second — and this is the substantive
contribution — the investigation uncovered two defects in the standard link-prediction evaluation
protocol. Correcting them reverses a widely repeated conclusion: under the conventional protocol the
simplest heuristics beat every embedding method on two of three graphs, while under the corrected
protocol the embeddings lead by +0.0459 (Citeseer) and +0.0212 (Facebook) with all ten splits in
favour.

## 1. Proposed Approach

### 1.1 Problem

Given an undirected graph `G = (V, E)`, assign a score `s(u, v)` to every non-edge such that pairs
likely to become edges rank higher. In the platform this is a concrete product question rather than
a metric question: for a given node, which candidates should be shown first.

The module covers the complete path from raw graph to ranked recommendation list, and is
self-contained with respect to algorithm implementation and experimental validation. It does not
handle the user interface, the task scheduler, or the storage layer; it consumes a graph and emits a
ranking.

### 1.2 Input

| Mode | Source | Notes |
|---|---|---|
| Platform | Social graph from the shared data layer (edge list, undirected, unweighted) | Module 4 performs ingestion, de-duplication, removal of self-loops and of edges with missing endpoints |
| Benchmark | SNAP public graphs: **Cora** (2 708 nodes / 5 278 edges), **Citeseer** (3 312 / 4 660), **Facebook** (4 039 / 88 234) | Used for comparison with published baselines |

Both modes share a single preprocessing contract: node identifiers are re-indexed deterministically;
edges are split into a training graph (80 %) and a held-out positive set (20 %); negative samples
are drawn from node pairs absent in the **training** graph, so the model never sees the answer.

### 1.3 Output and consumer

The module emits a ranked table, not a scalar metric:

| Column | Meaning |
|---|---|
| `query_node` | Node whose neighbourhood is being extended |
| `rank` | 1 = most likely candidate |
| `candidate` | Proposed neighbour |
| `score` | Calibrated probability in [0, 1] |
| `existing_edge` | Held-out true edge (`True`) versus genuinely new proposal (`False`) |
| `candidate_degree` | Degree in the training graph; lets the view filter cold-start items |
| `common_neighbours` | Shared-neighbour count, displayed as the justification for a recommendation |

This table feeds the recommendation view (top-K per node) and is written to the shared
experiment-record store, so that every displayed ranking is traceable to the run that produced it.

Output quality is measured over 200 randomly sampled Facebook nodes rather than on hand-picked
examples: **Precision@5 = 0.280 ± 0.281**, **Precision@10 = 0.228 ± 0.223**, against a random
baseline of 0.0175 — a lift of roughly 16×.

### 1.4 Method

The baseline family is DeepWalk / node2vec: random walks over the graph, Skip-gram training, the
Hadamard product of the two node vectors as an edge feature, and a logistic-regression classifier.

The proposed modification biases the walk itself:

```
P(v → x)  ∝  α(t, x) · w(v, x) · ( s(v, x) + β )^γ
```

| Symbol | Role | Values examined |
|---|---|---|
| `s(v, x)` | Local structural similarity of `v` and `x` | Jaccard, Resource Allocation (RA), Adamic-Adar (AA) |
| `β` | Smoothing term; guarantees non-zero probability where `s = 0`, so the walk degrades gracefully to uniform sampling in sparse regions | 0.2 (main), plus 0.05 and 1.0 |
| `γ` | Sharpening exponent; `γ = 1` is the linear form specified in the project plan | 0.5, 1, 2, 4, 8 |
| `α(t, x)` | node2vec second-order bias, with return parameter `p` and in-out parameter `q` | BFS-like `p = 0.5, q = 2`; DFS-like `p = 2, q = 0.5` |

Two design points distinguish this from post-hoc score fusion. First, the weighting changes the
sampled sequence, therefore the co-occurrence statistics that Skip-gram observes, therefore the
embedding — the structural prior is absorbed into the representation rather than added on top of it.
Second, the smoothing term is not a tuning knob but a correctness requirement: two adjacent nodes may
share no neighbour at all, in which case `s = 0` and an un-smoothed product would allow the walk to
absorb into a dead end.

The implementation is parameterised end to end — similarity kind, β, γ, p and q are independent —
which is what made the systematic ablation in Section 3 possible.

### 1.5 Baselines and evaluation metrics

| Group | Method | Rationale |
|---|---|---|
| Heuristic | Common Neighbours (CN) | Cheapest possible predictor; the bar any learned method must clear |
| Heuristic | Jaccard coefficient | Normalised by neighbourhood union |
| Heuristic | Adamic-Adar (AA) | Degree-penalised; strong on sparse graphs |
| Structural, degenerate | Degree product `deg(u)·deg(v)` | One scalar, no structural information. Included as a **canary**: if it scores well, the evaluation protocol is leaking degree |
| Representation learning | DeepWalk | Direct predecessor of the proposed method |
| Representation learning | node2vec (BFS-like, DFS-like) | Strongest published baseline |
| Proposed | Weighted walk, `s ∈ {Jaccard, RA, AA}` | — |

Five metrics are reported, because a single number can hide the effect under study:

- **AUC-ROC** — probability that a true edge outranks a non-edge; threshold-free.
- **Average Precision (AP)** — sensitive to the positive-class base rate, reported alongside AUC so
  that no conclusion rests on one metric alone.
- **Hits@10**, **Hits@50** — fraction of held-out edges appearing in the top 10 / 50 of a ranking
  against the negative pool. These match the product question.
- **MRR** — mean reciprocal rank of the held-out edge.

Protocol discipline, which proved to matter more than any hyper-parameter:

1. **Ten independent random edge splits** per configuration, reporting mean ± standard deviation, not
   a single split.
2. **Paired significance testing** across the same ten splits (paired t-test and Wilcoxon signed-rank).
   With ten splits, a difference smaller than the split-to-split spread cannot be claimed.
3. **Two evaluation protocols, A and B.** Protocol A is the conventional one: random negative samples
   and raw embedding vectors. Protocol B corrects two defects identified during this work
   (Section 3.2): negatives are degree-matched to the positives, and embeddings are normalised to
   unit length. Every method is reported under **both** protocols.

## 2. Related Work

### 2.1 Liben-Nowell & Kleinberg (2007) — problem formulation and the evaluation protocol

**What it does.** Formalises link prediction as a ranking problem over non-observed node pairs and
systematically compares neighbourhood-based scores (common neighbours, Jaccard, Adamic-Adar,
preferential attachment) on co-authorship graphs. Its lasting contribution, however, is the
evaluation convention that most subsequent work inherited: hold out a fraction of edges, sample an
equal number of negative pairs uniformly at random from the non-edges, and report AUC.

**Value for this module.** This is the source of the protocol audited in Section 3.2. Reading it
closely made clear that the negative-sampling step is an *assumption*, not a neutral detail: uniform
sampling over non-edges produces negatives whose degrees are far lower than those of real edges,
because real social links follow preferential attachment. That observation produced the
degree-matched sampling used in protocol B, and it is the single most useful thing drawn from the
paper.

> Liben-Nowell, D., & Kleinberg, J. (2007). The link-prediction problem for social networks.
> *Journal of the American Society for Information Science and Technology*, 58(7), 1019–1031.
> DOI: 10.1002/asi.20591

### 2.2 Perozzi, Al-Rfou & Skiena (2014) — DeepWalk

**What it does.** Treats the graph as a corpus: performs truncated uniform random walks from every
node, then applies the Skip-gram objective from word2vec to the resulting sequences, producing one
dense vector per node. Establishes that purely structural, unsupervised embeddings are competitive
with, and often better than, hand-crafted similarity indices.

**Value for this module.** DeepWalk is both the direct baseline and the scaffold that the proposed
method modifies; the only thing changed is the distribution from which the next hop is drawn.
Reproducing the reference implementation faithfully — same walk length, window size, dimension and
Skip-gram negative sampling — is what makes the comparison meaningful, because the difference between
the two methods then becomes attributable to the weighting rather than to implementation drift.

> Perozzi, B., Al-Rfou, R., & Skiena, S. (2014). DeepWalk: Online learning of social
> representations. In *Proceedings of the 20th ACM SIGKDD International Conference on Knowledge
> Discovery and Data Mining* (pp. 701–710). DOI: 10.1145/2623330.2623732

### 2.3 Grover & Leskovec (2016) — node2vec

**What it does.** Generalises DeepWalk's uniform walk with two parameters, `p` (return) and `q`
(in-out), interpolating between breadth-first and depth-first exploration. Shows that the homophily /
structural-equivalence trade-off is controlled by the walk bias, and that this single knob accounts
for a large part of the performance differences between embedding methods.

**Value for this module.** Two things. First, node2vec is the strongest baseline and it defines the
`α(t, x)` factor in the proposed transition probability — the joint form
`α · w · (s + β)^γ` is deliberately designed so that the p/q bias and the structural weighting are
separable, which is what allows the ablation to attribute effects. Second, its central claim (walk
bias determines what the embedding captures) is the hypothesis this module tests from a different
direction: node2vec biases by *distance from the previous node*, this module biases by *local
structural overlap*, and the experiments ask whether the latter adds anything the former has not
already captured.

> Grover, A., & Leskovec, J. (2016). node2vec: Scalable feature learning for networks. In
> *Proceedings of the 22nd ACM SIGKDD International Conference on Knowledge Discovery and Data
> Mining* (pp. 855–864). DOI: 10.1145/2939672.2939754

*Supporting references for individual indices:* Adamic, L. A., & Adar, E. (2003). Friends and
neighbors on the Web. *Social Networks*, 25(3), 211–230. DOI: 10.1016/S0378-8733(03)00009-1.
Zhou, T., Lü, L., & Zhang, Y.-C. (2009). Predicting missing links via local information.
*European Physical Journal B*, 71(4), 623–630. DOI: 10.1140/epjb/e2009-00335-8.

## 3. Current Progress

### 3.1 Completed

1. **End-to-end pipeline.** Graph loading with deterministic re-indexing, edge splitting, negative
   sampling, weighted walk generation, Skip-gram training, edge-feature construction, classification
   and evaluation. CPU only; one configuration on Cora takes about 16 s, which is what makes
   ten-split repeated evaluation affordable.
2. **Seven methods reproduced on three graphs**, ten independent splits each — three heuristics,
   three representation-learning baselines, and the weighted walk in three similarity variants, plus
   the degree-product canary.
3. **Structural weighting implemented and ablated.** Embedding dimension saturates between 64 and
   128; walk length between 10 and 80 moves AUC by less than 0.006 — so the bottleneck is the
   weighting design, not the sampling budget.
4. **Two evaluation protocols (A and B) implemented**, with every method reported under both.
5. **A reproducibility defect found and fixed** (Section 3.2a).
6. **Ranking output for the platform**, with measured quality (Section 1.3).

### 3.2 Two findings that changed the conclusions

#### (a) The pipeline was not reproducible

The same configuration with the same seed produced AUC values differing by up to **±0.01** when run
in a fresh process, while the effects being measured were of order **0.004**. Two root causes were
located: graph construction stored string node identifiers in a `set` before insertion, and
`networkx.non_edges` internally iterates `set(graph)`. Both make node and edge ordering depend on
`PYTHONHASHSEED`, so the same seed selected a different held-out edge set and a different negative
pool.

Fix: sort identifiers before insertion; replace `non_edges` with a deterministic enumeration; sort
degree buckets by `(degree, node_id)`; run with `PYTHONHASHSEED=0` and single-threaded Skip-gram.
Verified in two ways — two consecutive in-process runs return bit-identical scores, and a
fresh-process re-run reproduced the entire Cora table (ten methods × two protocols × AUC and AP) to
every reported digit.

#### (b) The conventional protocol over-rewards degree

Two independent defects compound each other.

**Random negatives under-represent high-degree nodes.** Real edges follow preferential attachment, so
uniformly sampled negatives have much lower degrees than the positives. A classifier that knows
**only** the degree product reaches 0.83 AUC on Facebook and 0.63 on Cora under the conventional
protocol; with degree-matched negatives it collapses to 0.54 and 0.51 — chance level. The genuine
heuristics barely move (CN on Facebook: 0.9894 → 0.9484), which confirms that the correction removes
degree leakage rather than penalising every method equally.

![Figure 2. A one-number degree baseline (leftmost bar group in each panel) is rewarded by random
negatives and collapses to chance once negatives are degree-matched. The genuine heuristics are
almost unaffected.](fig_m4_1_protocol_leak.png){width=100%}

**Embedding magnitude is a degree proxy.** The Hadamard feature scales with the norms of the two
vectors, and word2vec vector norms correlate with node frequency, i.e. degree. A linear classifier
can therefore use "both endpoints are well-trained" as evidence for an edge. Sharpening the walk to
γ = 8 appears to gain +0.09 AUC on Citeseer (0.6542 → 0.7466); unit-normalising the vectors removes
almost all of it (→ 0.6561). The apparent gain was magnitude, not structure.

#### Consequence: a widely repeated conclusion reverses

Under protocol A the simplest heuristics beat every embedding method on Citeseer (0.6577 vs 0.6570)
and Facebook (0.9906 vs 0.9877). Under protocol B the embeddings lead by **+0.0459 on Citeseer**
(paired t p = 3.3 × 10⁻⁸) and **+0.0212 on Facebook** (p = 1.6 × 10⁻¹³), winning all ten splits in
both cases; on Cora the lead is +0.1015. The conclusion that "embeddings are not worth it on sparse
graphs" is an artefact of degree leakage.

**The structural weighting adds at most a negligible amount.** Paired tests under protocol B, each
against DeepWalk on the same ten splits:

| Graph | Ours (Jaccard) vs DeepWalk | Paired t p | Splits won | Reading |
|---|---|---|---|---|
| Cora | +0.0004 | 0.85 | 6/10 | indistinguishable |
| Citeseer | −0.0010 | 0.43 | 4/10 | indistinguishable |

The Facebook row is stated precisely rather than glossed over: the effect is statistically
detectable — same sign on all ten splits, p < 0.001 — yet its magnitude is 0.0016 AUC against a
standard deviation of 0.0009. It is real and irrelevant at the same time. The RA and AA variants sit
within noise of both DeepWalk and node2vec-DFS on every graph.

Ranking metrics agree independently, so the conclusion is not a property of AUC: Hits@10 on Cora is
0.4357 (DeepWalk) versus 0.4412 (Ours-Jaccard), MRR 0.2270 versus 0.2476 — both inside one standard
deviation; on Citeseer 0.4145 versus 0.4130 and 0.2238 versus 0.2507.

**A fourth fusion position was also tried.** Concatenating the normalised structural scores with the
embedding edge features and passing them to the same classifier does not exceed the embedding-only
version either (largest gain 0.0010; −0.0002 on Citeseer under protocol B). Since a linear classifier
on concatenated features subsumes post-hoc score fusion, the three fusion positions — sampling,
feature, output — have now all been tried and all give the same answer.

**Interpretation (still being validated).** Skip-gram already recovers neighbourhood overlap from the
co-occurrence statistics of an *unbiased* walk, so re-weighting the walk towards structurally similar
neighbours re-encodes information the model would have learned anyway, while reducing the diversity
of contexts per node. A secondary factor is that Jaccard does not penalise high degree, so it
reinforces the walk's existing preference for hubs instead of correcting it; the RA and AA variants,
which do penalise degree, are the ones that stay closest to the baselines.

### 3.4 In progress

Three lines are open, none of them blocking the group draft:

1. **Extending the fusion experiment to Facebook.** The hybrid predictor has been run on Cora and
   Citeseer. Facebook is the remaining configuration, and it is the most informative one: it is the
   densest graph and the only place where the weighted walk showed any detectable effect, so it is
   the case worth checking before the negative result is written up.
2. **Connecting the ranking output to the shared task manager.** The candidate table is currently
   produced by a batch script and written to a static CSV. The target state is that the
   recommendation view reads from the experiment-record store, so that every displayed ranking
   carries the run identifier that produced it. This is the only interface change module 4 needs
   from the platform side, and it is what the contract in Section 1.3 is written against.
3. **Packaging protocol B as a reusable module.** Degree-matched negative sampling and
   unit-normalised feature vectors currently live inside this module's evaluation code. Since
   modules 2, 3 and 5 also compare graph-derived methods, extracting it as a shared evaluation
   component avoids each module rediscovering the same two defects.

### 3.5 Next steps

1. **Broaden graph density coverage.** Facebook saturates near 0.99 under protocol A, with all
   methods within 0.005 of each other, so it cannot discriminate. Add a medium-density graph (DBLP
   co-authorship) and a small ego-network so that density is covered continuously rather than at two
   extremes. This is the prerequisite for any claim of the form "structural weighting helps when the
   graph is …".
2. **Add metric families to the ablation.** The current sweep covers Jaccard / RA / AA and the
   sharpening exponent. Degree-normalised combinations (RA × AA mixtures) and a density-adaptive
   choice of β are the two variants the results point at, since degree penalisation is what
   separates the variants that hold up from those that do not.
3. **Write up the negative result as part of the module report.** The deliverable is a working
   recommender *plus* a defensible statement of when structural weighting pays off; the second half
   currently exists only in the experiment logs.
